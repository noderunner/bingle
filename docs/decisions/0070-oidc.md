# 0070. Signing in with an OpenID Connect provider

Status: accepted (2026-10-31)

## Context

Stage 5 of [the accounts plan](../history/auth-and-accounts-plan.md) (§4): a generic OpenID
Connect client — "Sign in with Google", and the same for Authentik, Keycloak or Entra — with PKCE,
`state` and a nonce, and the linking rule the plan calls the classic takeover vector.

## Decision

- **Two direct dependencies**, as the plan chose: `golang.org/x/oauth2` and
  `github.com/coreos/go-oidc/v3` (which brings `go-jose/v4`). Ten direct dependencies now. Checking
  an ID token — discovery, the key set, the signature, issuer, audience and expiry — is the part
  of this a project should not write itself.
- **Providers** are configured, not built in: `BINGLE_OIDC_PROVIDERS=google,corp` and a
  `BINGLE_OIDC_<ID>_ISSUER`, `_CLIENT_ID`, `_CLIENT_SECRET` (or `_CLIENT_SECRET_FILE`), `_SCOPES`,
  `_LABEL` block each. They need `BINGLE_PUBLIC_URL`: the redirect is
  `<public URL>/auth/oidc/<id>/callback`, never one made from the request's `Host`. A provider is
  discovered on its first use, so one that is down does not stop bingle starting.
- **The flow.** `GET /auth/oidc/<id>/start` makes a state, a nonce and a PKCE verifier, keeps them
  in memory for ten minutes under the state's hash, puts the state in a `bingle_oidc` cookie and
  sends the browser on. The callback must bring back the state this browser holds, which spends it
  (a replayed or forged callback signs nobody in, and a callback finished in another browser does
  not either); the code is exchanged with the verifier, and the ID token must name the nonce.
- **The linking rule.** An identity already linked signs in to its account. Otherwise it links to
  an account by its address **only** when the provider says `email_verified` and the account's
  address is confirmed here; an address the provider does not vouch for, matching an account, is
  told to sign in with the password and link the provider from the account page. An identity that
  matches nobody becomes a new account once its person chooses a handle (`/signup?provider=`, a
  `bingle_oidc_new` cookie, then `POST /auth/oidc/finish`) — unless signing up is closed, or the
  provider does not vouch for the address.
- **A provider stands in for the password, not the second factor**: an account with TOTP is asked
  for its code after the provider, and the admin rule of ADR 0069 applies as before.
- **An account a provider made has no password.** It sets one on the account page (no old password
  to give), and cannot unlink its last way in.
- **Linking from the account page** (`?link=1`, signed in) links the identity to that account, and
  refuses one that is another account's.
- **`internal/auth/fakeoidc`** is a provider in the test's process, as `fakesmtp` is a mail server:
  discovery, an RSA key, an authorisation endpoint that approves whoever the test says, and a token
  endpoint that checks PKCE and spends each code once.
