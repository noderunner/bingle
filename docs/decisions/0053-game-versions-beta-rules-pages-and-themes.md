# 0053. Game versions and the Beta mark, one Rules page for the abstract games, coordinates outside themed frames

Status: accepted (2026-10-26)

## Context

`bingle_issues.md` asked for a list of games that shows a Beta mark and the players each game takes, with the details on hover instead of a summary, for the version of each game implementation to be tracked, and for the rules of the abstract games to be complete enough for a new player (Tak first, with diagrams) without tabs that only hold a table of piece names. It also asked for two themes to be calmer, a new gemstone theme, and for coordinates to stay readable on a themed board.

## Decision

- **Version, designers and publisher live in the game's JSON** (`version`, `designers[]`, `publisher`), next to its rules, so the version goes up in the same change that changes the game. A version is `major.minor.patch` (the catalog rejects anything else). Variants inherit the base document's, so a game has one version. Every game is **0.1.0**; the rule from now on is to raise it with each change to a game's definition or Go code, and to stay below 1.0.0 until the owner calls the game out of beta. `GET /game-defs` (and MCP `list_game_defs`) carry `version`, `designers`, `publisher`.
- **The database keeps the history** in `game_versions (family, version, first_seen)`. The server records the version of every game family it starts with (`INSERT OR IGNORE`, so once each however often it restarts). The rows are for the owner (and later tools); nothing reads them to decide anything.
- **The engine has a version of its own**, `version.Engine` in `internal/version` (starting at **0.3.0**, since there was none): raise it for a change to the engine or the platform (server, DSL, shared rules code, web client), not for a change to one game. Every page ends with it in small type (`.site-footer`, from the templates) and `/healthz` reports it.
- **The list of games** (`home.js`): the card is the picture, the name, a **Beta** mark (a version below 1.0.0, with the version as its title) and the players the game takes (the seat counts of the game and its variants: `2 players`, `3–5 players`). The summary and the board-size chips are gone; the sizes are chosen in the setup. A card shown while the pointer is over a game (or it has the focus) gives the name, designers, publisher (left out when not known), the description and the version. Cthulhu Wars shows the four core sigils and Hive a cluster of tiles (`js/game-icons.js`). The *Read the rules* button of the setup is *Rules*. Amazons is no longer "Game of the Amazons".
- **One Rules page.** The abstract games ship a guide of their own: a single **Rules** tab with the whole rules, a section on the move notation and diagrams where movement, capture or a winning shape need one. Games whose pieces need explaining keep a page for them (Fist's pieces, Hive's tiles, Onitama's cards). A game with no guide gets a generated single *Rules* page (no table of pieces). Tak has the sections the owner listed: Stacking & Movement, Roads, Walls and The capstone. Diagrams are static SVG files, drawn by `scripts/guide_diagrams.py` (so a change is a change to the script) with opaque colours of their own, so they read in light and dark. Onitama's card page and picture are drawn by the game's Go code from its card table, so they cannot disagree with the rules. The classics and Tak became modules with `Assets` (a folder of Markdown and SVG each).
- **Pictures of games that start empty** (Gomoku, Go, Hex, Yavalath, Havannah, Pente, Connect Four, Tic-Tac-Toe, Tak, Blooms, Yinsh, Courtfall): a game's JSON may carry `preview`, a sample game in play (entries like `setup`, stacking on one square from the bottom up; squares the board lacks are skipped so a smaller variant can inherit it). `GET /game-defs/{id}` returns it as `preview` and the list and the setup page draw it in place of the start. Nyet!, which has no board, got a picture of cards.
- **The footer and a help button.** The footer of every page says `bingle v… · MIT License · GitHub`, and the top bar has a **?** (the version first, a link to the repository, *Report Issues*). The hover card of a game leaves out what is not known (a bug wrote "null" for a missing publisher), and an unknown designer (the traditional games, Fist, the demo) is left out instead of being "Traditional".
- **Themes.** Hot Synthwave Vibes is a plain dusk sky with its neon border (no stars, sun, grid or chevrons) and the Moroccan Bazaar a quiet lattice and plain plaster cells (no corner stars). **Precious Gemstones** is a new theme: velvet, facets, a gold rail set with gems, stones cut as ruby, citrine, fire opal, diamond (warm) and sapphire, onyx (cold). With a theme on, the coordinates move to a strip outside the frame, in the text colour of the page (the frame stays a rectangle; the picture's `viewBox` grows by the strip).

## Interpretations

"Board size markings" are the chips of the variants under a card (Tak's 3×3 … 8×8) and the "(15×15)" of Gomoku's name in the list; the sizes are chosen in the setup as before. A game whose designer is unknown (the traditional games: Go, draughts, Tic-Tac-Toe, Gomoku, Brandubh; Fist; the demo) lists no designer, and the hover card leaves the line out. Courtfall's designer is its author. A publisher is only given where it is certain (Cheapass Games, Hasbro, nestorgames, Gen42 Games, Arcane Wonders, Petersen Games). The number of players is the range of the seat counts of the family, not a field of its own, so it cannot drift. Hive, Fist, Courtfall and Nyet keep their own guides; the first tab of Hive and Fist is called *Rules* (it was *Overview*). Cthulhu Wars keeps its split into many tabs.
